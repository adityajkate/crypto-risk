# PRD — Crypto Risk Lens Backend

---

## 1. Product Summary

Crypto Risk Lens is a real-time cryptocurrency risk analysis system. It ingests live market data and news, engineers technical and sentiment features, and runs trained ML models to classify risk levels, detect market regimes, forecast volatility, and extract sentiment signals. The backend is a FastAPI REST API. There is no database — all persistence is through filesystem artifacts (joblib, CSV) and all runtime state lives in memory with TTL-based caching.

---

## 2. System Constraints

- No database. No SQL, no NoSQL, no ORM.
- Trained models stored as `.joblib` files in an `artifacts/` directory.
- Models loaded into memory once at server startup.
- All external data fetched in real-time from public APIs with in-memory TTL caching to respect rate limits.
- No buy/sell/trade recommendations. Output is informational risk and sentiment insight only.

---

## 3. Data Sources

| Source | What It Provides | Refresh Interval (Cache TTL) |
|---|---|---|
| CoinGecko API (free tier) | Current price, market cap, 24h volume, OHLC candles, historical price+volume time series | 5 minutes |
| CryptoPanic API | Crypto news headlines with source, timestamp, mentioned currencies | 10 minutes |
| Alternative.me API | Fear & Greed Index — current value, classification, and historical values | 30 minutes |
| Kaggle CSV (offline only) | Historical BTC/ETH daily OHLCV data used exclusively for model training | One-time load during training |

All API calls are asynchronous using `httpx.AsyncClient`. Every fetcher function is wrapped with an in-memory TTL cache decorator. Cache is a simple dictionary mapping `function_name + args` to `(timestamp, result)`. If the cached entry is within TTL, return it. Otherwise, re-fetch.

## 4. Feature Engineering

### 4.1 Market Features (from OHLCV data)

Computed using TA-Lib and Pandas on every inference request after fetching live data.

| Feature | Description |
|---|---|
| `returns_1d` | Daily percentage return |
| `log_returns` | Natural log of price ratio (normalized return) |
| `volatility_7d` | Rolling 7-day standard deviation of log returns |
| `volatility_30d` | Rolling 30-day standard deviation of log returns |
| `rsi_14` | Relative Strength Index, 14-period |
| `macd`, `macd_signal`, `macd_hist` | MACD(12,26,9) components |
| `bb_upper`, `bb_lower`, `bb_width` | Bollinger Bands(20,2) and their normalized width |
| `atr_14` | Average True Range, 14-period |
| `obv` | On-Balance Volume |
| `volume_sma_ratio` | Current volume divided by 20-day volume SMA (spike detector) |
| `drawdown` | Current price vs rolling all-time-high, as a negative percentage |
| `price_sma50_ratio` | Price divided by 50-day SMA |
| `price_sma200_ratio` | Price divided by 200-day SMA |

The feature engine is a stateless class. It takes a DataFrame with columns `[timestamp, open, high, low, close, volume]`, appends all computed columns, drops rows with NaN (from rolling windows), and returns the enriched DataFrame.

### 4.2 Sentiment Features (from news headlines)

| Feature | Description |
|---|---|
| `sentiment_compound` | VADER compound score per headline (-1 to +1) |
| `sentiment_avg_24h` | Mean compound score across all recent headlines |
| `sentiment_std_24h` | Standard deviation of compound scores (disagreement measure) |
| `news_volume_24h` | Total number of articles fetched |
| `negative_ratio` | Fraction of headlines with compound < -0.05 |
| `positive_ratio` | Fraction of headlines with compound > 0.05 |
| `neutral_ratio` | Fraction of headlines between -0.05 and 0.05 |
| `dominant_themes` | Top 5 keywords/bigrams extracted via TF-IDF from headline corpus |

Sentiment classification per headline: compound ≥ 0.05 → positive, ≤ -0.05 → negative, else neutral.

## 5. Risk Label Generation (for training only)

Risk labels are not manually assigned. They are computed from a composite risk score:

1. Normalize `volatility_30d` to [0,1] range (min-max across training set).
2. Normalize absolute `drawdown` to [0,1].
3. Compute volume spike as `max(0, volume_sma_ratio - 1)`, normalize to [0,1].
4. Composite score = `0.5 × normalized_volatility + 0.3 × normalized_drawdown + 0.2 × normalized_volume_spike`.
5. Bucket composite score into 3 classes using `pd.qcut` (equal-frequency percentile split):
   - Label 0 → Low Risk
   - Label 1 → Medium Risk
   - Label 2 → High Risk

This produces balanced classes grounded in actual market behavior, not arbitrary thresholds.

## 6. Model Training Pipeline

All training happens offline via standalone Python scripts. Each script reads processed CSV data, trains models with proper validation, prints evaluation metrics, and saves artifacts as `.joblib` files into the `artifacts/` directory.

### 6.1 Data Preprocessing (run first)

- Read raw Kaggle CSVs.
- Normalize column names, parse timestamps, sort chronologically, remove duplicates.
- Forward-fill small gaps in OHLCV data.
- Run the market feature engine to compute all technical features.
- Save as processed CSV.

### 6.2 Risk Classifier

**Models trained:** Logistic Regression, Random Forest, XGBoost.

**Validation:** TimeSeriesSplit with 5 folds (no random shuffle — respects temporal order).

**Preprocessing:** StandardScaler fitted on training data, saved as artifact.

**Hyperparameters:**
- Logistic Regression: multinomial, max_iter=1000, C=1.0, class_weight=balanced.
- Random Forest: 300 trees, max_depth=10, min_samples_leaf=20, class_weight=balanced.
- XGBoost: 300 estimators, max_depth=6, learning_rate=0.05, subsample=0.8, colsample_bytree=0.8, multi:softprob objective.

**Evaluation:** Weighted F1 score per fold, averaged. Full classification report on last fold. Best model name saved in a metadata artifact.

**Artifacts saved:** `risk_logreg.joblib`, `risk_rf.joblib`, `risk_xgb.joblib`, `risk_best.joblib` (metadata pointing to best), `scaler.joblib`.

### 6.3 Volatility Regression

**Target variable:** Forward 7-day realized volatility (rolling 7-day std of log returns, shifted back).

**Models trained:**
- Linear Regression (sklearn) — evaluated with MAE and R² across TimeSeriesSplit.
- Quantile Regression (statsmodels) at quantiles 0.1, 0.5, 0.9 — gives confidence intervals for volatility forecast.

**Feature subset:** `volatility_7d`, `volatility_30d`, `rsi_14`, `atr_14`, `bb_width`, `volume_sma_ratio`, `drawdown`, `price_sma50_ratio`, `macd_hist`.

**Artifacts saved:** `volatility_linreg.joblib`, `volatility_qreg_10.joblib`, `volatility_qreg_50.joblib`, `volatility_qreg_90.joblib`, `regression_features.joblib` (ordered feature list).

### 6.4 Market Clustering

**Models trained:** K-Means, Agglomerative Hierarchical Clustering (Ward linkage).

**Feature subset:** `volatility_7d`, `volatility_30d`, `returns_1d`, `volume_sma_ratio`, `rsi_14`, `bb_width`, `drawdown`.

**Preprocessing:** Separate StandardScaler for clustering features, saved as artifact.

**Optimal K selection:** Iterate K from 2 to 6, pick K with highest silhouette score.

**Output:** Cluster profiles (mean of each feature per cluster) saved as CSV for interpretability.

**Artifacts saved:** `kmeans_market.joblib`, `hierarchical_market.joblib`, `cluster_scaler.joblib`, `cluster_features.joblib`, `cluster_profiles.csv`.

### 6.5 Regime Detection

**Hidden Markov Model:**
- GaussianHMM from `hmmlearn`.
- Observation variables: `log_returns` and `volatility_7d` (2D).
- Test n_states = 2, 3, 4. Select by lowest BIC = `-2 × log_likelihood + n_params × ln(n_observations)`.
- After fitting, decode hidden states. Compute per-regime profiles (mean return, mean volatility, mean volume ratio, mean drawdown).
- Name regimes by sorting on mean volatility: lowest → `low_vol_stable`, next → `moderate_transition`, highest → `high_vol_crisis`.

**Change-Point Detection:**
- `ruptures` library, PELT algorithm with RBF kernel, min_size=10, penalty=3.
- Applied on log returns series.
- Output: list of indices and corresponding timestamps where structural breaks occurred.

**Artifacts saved:** `regime_hmm.joblib`, `regime_names.joblib` (mapping of state ID → human name), `change_points.joblib` (indices + dates).

### 6.6 PCA

- Applied on all 14 market features after StandardScaler.
- Retain components explaining 95% cumulative variance.
- Print number of components retained, explained variance ratios, and top 3 feature loadings per component.
- PCA-transformed features can optionally be used as inputs to other models for dimensionality-reduced inference.

**Artifacts saved:** `pca_transformer.joblib`, `pca_scaler.joblib`, `pca_features.joblib` (ordered input feature list).

## 7. Inference Logic

### 7.1 Model Loading

At FastAPI startup (lifespan handler), a `ModelStore` singleton loads every `.joblib` file from `artifacts/` into a Python dictionary. If a file is missing, it logs a warning but doesn't crash — the corresponding endpoint will return a graceful error.

### 7.2 Risk Assessment Inference

1. Fetch 90-day price + volume history from CoinGecko for the requested coin.
2. Convert into a DataFrame with `[timestamp, open, high, low, close, volume]`.
3. Run the feature engine to compute all technical indicators.
4. Extract the last row (latest market state).
5. Select the model's expected feature columns, apply the saved `StandardScaler`.
6. Run `predict()` and `predict_proba()` on all three classifiers (LogReg, RF, XGB).
7. Use the best model (from metadata artifact) as the primary result.
8. Also run the linear regression model on the regression feature subset to get a 7-day volatility forecast.
9. Fetch current Fear & Greed value.
10. Return: risk level (low/medium/high), confidence (max probability), per-class probabilities, all-model comparison, volatility forecast, Fear & Greed value, and current market stats (price, volatility, RSI, drawdown, BB width).

### 7.3 Sentiment Inference

1. Fetch latest 50 headlines from CryptoPanic.
2. Optionally filter by coin currency code.
3. Run VADER on each headline to get compound/positive/negative/neutral scores and classify.
4. Compute aggregate features: mean compound, std, news volume, negative/positive/neutral ratios.
5. Run TF-IDF on headline texts, extract top 5 terms by mean TF-IDF weight as dominant themes.
6. Fetch current Fear & Greed value.
7. Return: all aggregate sentiment features, dominant themes, top 10 scored headlines, and Fear & Greed data.

### 7.4 Regime Detection Inference

1. Fetch 180-day price + volume history from CoinGecko.
2. Compute features.
3. Feed `[log_returns, volatility_7d]` into the loaded HMM.
4. Call `predict()` for state sequence and `predict_proba()` for state probabilities.
5. Identify current state, map to human-readable name via `regime_names` artifact.
6. Compute persistence probability from transition matrix (diagonal element for current state).
7. Return last 30 entries of regime history with timestamps.
8. Also run the K-Means model on the latest row's cluster features to get cluster assignment and distance to cluster center.
9. Return: current regime name, state probabilities, persistence probability, regime history, cluster info, full transition matrix.

### 7.5 Dashboard Aggregation

Single endpoint that calls risk assessment, sentiment analysis, and regime detection internally, fetches current price data, and returns everything in one unified JSON response with a timestamp.

## 8. API Endpoints

| Method | Path | Description | Response Highlights |
|---|---|---|---|
| GET | `/health` | Server + model load status | `{ status, models_loaded }` |
| GET | `/market/price/{coin_id}` | Live price and market stats | Price, market cap, volume, 24h/7d/30d changes, ATH info |
| GET | `/market/ohlc/{coin_id}?days=90` | OHLC candle data | List of `{ ts, open, high, low, close }` |
| GET | `/market/chart/{coin_id}?days=90` | Price + volume time series | `{ prices, volumes, market_caps }` |
| GET | `/sentiment/current?coin_filter=BTC` | Live sentiment analysis | Avg sentiment, ratios, themes, scored headlines, Fear & Greed |
| GET | `/sentiment/fear-greed?days=30` | Fear & Greed history | List of `{ value, classification, timestamp }` |
| GET | `/risk/assess/{coin_id}?days=90` | ML risk classification | Risk level, confidence, probabilities, all models, vol forecast |
| GET | `/risk/historical/{coin_id}?days=365` | Risk level time series | List of `{ timestamp, risk_level, confidence, price }` |
| GET | `/regime/detect/{coin_id}?days=180` | HMM regime + clustering | Current regime, state probs, persistence, history, cluster |
| GET | `/regime/change-points/{coin_id}` | Structural break dates | List of change-point timestamps |
| GET | `/dashboard/summary/{coin_id}` | Combined everything | Market + risk + sentiment + regime in one response |

All endpoints return JSON. Pydantic models enforce response schemas. Errors return standard HTTP error codes with detail messages.

## 11. Execution Sequence

1. Install all dependencies.
2. Place raw historical CSVs in `training/data/raw/`.
3. Run `preprocess.py` to generate processed feature CSVs.
4. Run each training script in order: risk classifier → regression → clustering → regime → PCA.
5. Verify all `.joblib` artifacts exist in `artifacts/`.
6. Set environment variables for API keys (`CRYPTOPANIC_API_KEY`).
7. Start the server: `uvicorn app.main:app --host 0.0.0.0 --port 8000`.
8. On startup, all models load into memory. Server is ready to serve requests.

---

## 12. Non-Functional Requirements

- All training uses TimeSeriesSplit (no data leakage from future to past).
- No random train-test splits anywhere. Temporal order is always preserved.
- Every model prints evaluation metrics during training. No silent saves.
- CORS enabled for all origins (frontend integration ready).
- Graceful degradation: if a model artifact is missing, that specific endpoint returns an error but the rest of the server works fine.
- No financial advice in any response. Outputs are analytical indicators only.
